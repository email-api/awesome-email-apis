# Contributing

Thank you for improving this list.

## Adding an entry

1. Confirm the project fits a **developer email API / related tool** audience (app send, not newsletter design galleries alone).
2. Use the correct section (transactional API, broader platform, self-hosted, testing).
3. Keep descriptions factual (1–2 sentences). No “best”, “#1”, or unverified benchmarks.
4. Link the **official** homepage or source repository.
5. Label hosted SaaS and open-source software correctly.
6. Insert **alphabetically** within the section.
7. Open a PR with a short rationale.

## Updating an entry

Fix broken links, outdated product names, or incorrect categorisation. Prefer citing an official changelog or docs URL in the PR description.

## Removals

Do not remove entries solely because a site was briefly down or a repo is quiet. Open an issue noting the problem so maintainers can review.
